# Canonical covariance-adaptive importance sampling

[`CAIS`](@ref) implements the canonical covariance-adaptive importance
sampler in Section III-B of El-Laham, Elvira, and Bugallo,
[“Robust Covariance Adaptation in Adaptive Importance Sampling”](https://doi.org/10.1109/LSP.2018.2841641).
The [author-hosted paper](https://victorelvira.github.io/assets/papers/el2018robust_pre.pdf)
contains the displayed recurrence in equations (5)--(10).

```julia
using ImportanceSamplers, Random

bank = ProposalBank([
    SphericalGaussian(-3.0, 1.5),
    SphericalGaussian(3.0, 1.5),
])
algorithm = CAIS(bank; rounds=4, round_size=4_000)
prepared = prepare_sampler(Xoshiro(42), x -> -abs2(x) / 2, algorithm)
samples = importance_sample!(prepared)
learned = current_proposal(prepared)
```

Every round allocates the same number ``m`` of samples to each proposal.
Consequently, every bank mass must be equal and positive, and `round_size`
must divide exactly by the proposal count. One proposal is valid. CAIS needs
at least ``m \ge d + 2`` samples per proposal in dimension ``d`` so an
unregularized covariance fit has enough observations.

## Weights, means, and covariances

For a sample generated by proposal ``q_{i,j}`` in round ``i``, the retained
standard importance weight is

```math
w_{i,j}^{(n)} =
\frac{\pi(x_{i,j}^{(n)})}{q_{i,j}(x_{i,j}^{(n)})}.
```

Thus `samples.logweights` contains `logtarget - log(generating proposal)`.
It is not a deterministic-mixture denominator. The raw weights from every
round remain in the returned result with their generating round and proposal
provenance; they are never recomputed under a later population.

Within each proposal group, CAIS normalizes those raw weights and always fits
the next mean

```math
\mu_{i+1,j}=\sum_n \bar w_{i,j}^{(n)}x_{i,j}^{(n)}.
```

The covariance center depends on the raw local effective sample size (ESS):

- If the raw ESS is at least the threshold, the covariance uses the raw
  normalized weights and is centered at the **old generating mean**
  ``\mu_{i,j}``, not at the fitted next mean.
- If the raw ESS is below the threshold, the implementation power-tempers the
  local weights until their ESS reaches the threshold. The covariance uses
  those transformed weights and is centered at their transformed weighted
  mean. The proposal's next mean remains the raw-weight mean above.

Power tempering is one of the paper's two transformations. The bounded
log-space bisection tolerance `1e-4` and 16-iteration limit are package-owned
numerical choices, not paper defaults. `diagnostics.local_ess` records the ESS
of the weights actually used for covariance fitting: it is the raw ESS when
`diagnostics.tempering_powers == 1`, and the post-tempering ESS otherwise.

The paper requires ``d < N_T < m`` but does not prescribe a universal
threshold. An explicit `covariance_ess_threshold=N_T` must satisfy that strict
range in every round. With `nothing`, the package chooses
`max(d + 1, ceil(Int, 0.3m))` independently for each round. This is a package
default.

## Exact replacement and failure

CAIS replaces every covariance outright. It does not blend with the old
covariance, add a ridge, floor eigenvalues, or silently retain an old factor.
Local ESS alone cannot make repeated or otherwise degenerate samples positive
definite. All-zero local weights, an unreachable positive tempering solution,
or failed Cholesky factorization therefore throws [`CAISRoundError`](@ref).

Each call is transactional. Failure retains the complete pre-call proposal
population, including covariance factors and Gaussian log normalizers, while
the owned RNG remains advanced. Success commits the fit after the final round.
Repeated calls start from that learned population, and `retarget` carries it
into the fresh sampler.

Scalar proposal inputs remain scalar in returned samples and snapshots.
Vector inputs learn dense lower-triangular factors even when the initial
proposal was spherical or diagonal.

## CPU and CUDA

CPU execution honors `threaded=false`. CUDA uses cooperative local reductions
and keeps samples, weights, covariance scratch, and learned state resident;
only bounded round diagnostics cross to the host. Transfer the complete
prepared sampler explicitly:

```julia
using CUDA, MLDataDevices
physical = CUDA.device()
device = MLDataDevices.CUDADevice{typeof(physical),Nothing}(physical)
prepared = device(prepare_sampler(Xoshiro(43), x -> -abs2(x) / 2, algorithm))
samples = importance_sample!(prepared)
host_learned = current_proposal(cpu_device(), prepared)
```

For an all-`Float32` CUDA path, construct the bank with explicit `Float32`
masses, for example `ProposalBank(proposals, Float32[1, 1])`. As elsewhere in
the package, bank masses participate in numeric type promotion.

See the [teaching example](https://github.com/BJMCox/ImportanceSamplers.jl/blob/main/examples/cais.jl),
[real-CUDA reproducer](https://github.com/BJMCox/ImportanceSamplers.jl/blob/main/validation/reproducers/cuda_cais.jl),
and [benchmark harness](https://github.com/BJMCox/ImportanceSamplers.jl/blob/main/benchmark/cais.jl).
